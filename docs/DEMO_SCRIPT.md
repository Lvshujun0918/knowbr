# 知行桥 演示脚本（5—7 分钟录屏用）

**演示前准备**

```bash
cd web && pnpm install && pnpm test && pnpm build
cd ../server && go run .          # 单端口演示：http://127.0.0.1:8080
```

1. 确认首页右上角徽标显示「规则模板模式」（未配置 API Key 时无需任何外部服务）；若已配置 `ZXQ_LLM_*`，这里会显示大模型增强模式与模型名。
2. 清空历史记录，保证录屏从干净状态开始：首页 → 学习记录 → 清空全部。
3. （可选）录屏前跑一次 `make check`，用于在讲解"工程质量"时展示命令与结果。

> **讲解口径**：以下案例数据均为**人工构造的教学演示数据**，不是真实训练实验结果，也不代表任何真实学生的学习成效。系统展示的所有指标都由程序计算；是否真的调用过大模型会在界面上标注。

---

## 第 0 段（0:00—0:35）产品定位与覆盖范围

打开首页，指向标题与一句话介绍：**以实验结果为证据，通过诊断、分层提示和迁移检验，帮助学生真正理解人工智能实验。**

强调三点：

1. 它不是课程问答机器人，也不替学生写代码——判断依据来自学生提交的证据；
2. 首页右侧「已覆盖的教学场景」直接来自服务端规则库：**7 个任务类型 · 16 条典型误区规则 · 10 个演示案例**（分类指标、模型结构、训练稳定性、环境排障、回归、聚类、数据预处理），这一块不会被写成"支持一切"；
3. 未覆盖的课程模块不会声称已支持——这是产品的诚实边界，也是评委最容易验证的一点。

---

## 第 1 段（0:35—1:15）加载演示案例并提交

1. 点击「体验演示案例」→ 自动载入**案例一：类别极不平衡的三分类任务**。其余 9 个案例可在提交页点「加载演示案例」选择。
2. 快速带过表单：实验名称、类别分布（A 900 / B 90 / C 10，共 1000）、混淆矩阵、评价指标、学生解释「我的模型准确率达到 90%，所以我认为模型效果很好，可以直接使用了」。
3. 说明：混淆矩阵既可粘贴也可用表格填写，界面实时调用后端计算校验——**故意输错一格**（例如填一个负数，或让某行少一列），展示中文定位提示，并强调**已填内容不会被清空**。
4. 点击「开始诊断」。

---

## 第 2 段（1:15—2:20）诊断结果

1. 顶部先看「任务类型」标签：诊断、提示与迁移题都限定在这一任务范围内。
2. 「主要问题」引用具体数据（准确率 90%、B/C 召回率为 0），并提示规则只能定位问题、不能替代学生自己的判断。
3. 「逐条主张诊断」：学生的每个主张被单独判断（本例命中"只用整体准确率"），给出学生原话、判断、原因、证据边界与下一步追问。
4. 右侧「材料必要性」区分必需与可选材料；「知识点状态」标出已掌握 / 部分掌握 / 未涉及，并写明**未涉及不等于未掌握**。

依次讲解：

- **问题类型**：实验结果解释问题 + 评价指标选择问题。
- **证据**：分为「学生原话」与「由你提交的矩阵计算」两类来源。读出：总样本 1000、正确 900、准确率 90.0%；类别 B 的 90 个样本全部被预测为类别 A，召回率 0%。
- **指标表**：逐类召回率 100% / 0% / 0%，宏平均 F1（≈0.316）与加权平均 F1（≈0.853）的差距——正是类别不平衡的信号；表格标注「由程序计算」与零分母约定。
- **建议下一步**：逐类计算召回率并判断少数类是否可用。

---

## 第 3 段（2:20—3:45）分层辅导与智能体决策

1. 点「给我一级提示」——只给观察方向（看 B、C 两行的去向），读出提示尾部引用的真实数据（"（引用你提交的数据：…）"）。
2. **重点演示智能体决策**：右侧「智能体决策」卡片显示它当前决定做什么、为什么这么做；点「让智能体决定下一步」——系统**自己**给出下一级提示（不是学生点出来的），并说明这是系统判断。
3. 展开「智能体运行了哪些检查？」：四条工具轨迹都是真实结果——证据完备性（必需材料几项齐备）、指标计算（总样本/准确率/宏平均 F1/召回率为 0 的类别）、提示与修正进度、本机历史查询。
4. 展开「长期记忆（本机历史记录 N 条）」：如果此前的记录里出现过同一误区，这里会写明"该误区此前出现过 N 次"，并据此**从一级提示重新引导**而不是重复概念解释；卡片底部如实标注"记录按本机归并、无法确认是否同一名学生"。
5. 在输入框写下「B 和 C 都被预测为 A，说明模型没有识别出这两个类别，召回率为 0」，提交 → 「有所修正」反馈 + 已覆盖/仍缺少要点。
6. 点「查看局部示例」——给出 `0 / 90 = 0%` 的局部计算，强调**答案不是一次给完的**。
7. （可选，10 秒）证据不足的对照：回提交页只填"准确率 90%"→ 开始诊断 → 智能体拒绝直接给示例，改为列出"需要你补充的材料"。

---

## 第 4 段（3:45—4:55）迁移测试

1. 点「进入迁移测试」——题目由规则模板按当前任务类型（本例分类指标）与命中的问题类型组合生成，情境与数据条件都与原题不同。
2. 展开「这道题是怎么生成的？」：读出题目来源（规则模板组合生成）、选题依据（任务类型 + 命中的问题类型）、本次参数与重复检查结果（与示例情境的相似度）。
3. **强调门禁**：此时页面上只有题目、评分维度与评分口径声明，**没有参考答案入口**；提交自己的答案后才出现「查看参考答案」。
4. 输入答案：正样本占比很小，属明显不平衡；准确率会误导；主指标看召回率，用精确率控制误报，按可接受的错误代价调整阈值，并用混淆矩阵核对两类错误数量。
5. 提交 → 三个维度逐条给分并说明理由（得分 6/6 时也会写明"为什么满分"），此时才出现「查看参考答案」。
6. 读出评分口径声明：分数只代表本次演示任务的规则化反馈，不等于考试成绩。

---

## 第 5 段（4:55—6:05）学习反馈与教师视图

1. 点「完成本次学习」→ 学习反馈页：学习目标、逐条主张与知识点状态、关键证据、提示轨迹、修正情况、迁移表现与评分依据、当前掌握情况、建议学生继续学习、建议教师关注的问题。
2. 演示「复制反馈」与「导出 Markdown / TXT」。
3. 打开「教师视图」：顶部统计条、共性问题（含出现次数与涉及记录）、逐条记录摘要；读出免责说明——**统计只来自本机已保存的记录，不是真实班级或成绩统计**。
4. 打开「学习记录」：展示本次记录（状态「已完成学习」、迁移得分），刷新验证记录仍在（服务端 SQLite 持久化），再演示删除单条与清空全部。

---

## 收尾（6:05—6:35）

回到首页做三点收束：

1. **三种运行模式**：`demo` 预置演示、`rule` 规则模板（无 Key 即可完整运行）、`llm` 大模型增强（配置 Key 后启用；只让模型组织自然语言，指标与类别仍由程序计算）。
2. **诚实边界**：不运行学生代码；模型输出里的数值必须能在学生材料或程序计算结果里找到，否则整段回退并写明是哪个数值；评分不是考试成绩；教师统计不冒充班级统计。
3. **工程质量**：`make check` 一条命令跑完后端 vet/test/build 与前端单元测试 + 类型检查 + 打包，GitHub Actions 跑同样的两步。

---

## 4 分钟精简版动线

首页（15s）→ 体验演示案例 + 开始诊断（20s）→ 诊断页读出证据与指标表（45s）→ 分层辅导：一级提示 + **让智能体决定下一步** + 工具轨迹（60s）→ 迁移测试：门禁与评分（50s）→ 学习反馈 + 教师视图（40s）→ 收尾三句话（20s）。

## 备选片段（时间有余时）

- **案例二**：只提交准确率 → 诊断为「证据不足」并追问类别分布与任务目标，示范系统不武断下结论。
- **案例三**：误读混淆矩阵 → 指出陈述与证据矛盾（100 个样本不在对角线上），语气中性、不贬低学生，并建议教师介入。
- **案例五**：环境报错 → 直接给出可执行的排障步骤（`pip install`、打印路径、检查形状），不用苏格拉底式提问。
- **案例六**：MLP 与 CNN 对比 → 同一段话里的三个推理问题被分别诊断（结构差异 / 容量匹配 / 单一测试结果）。
- **案例七**：RNN 训练损失异常 → 诊断引用日志数值、三级提示不出现混淆矩阵或类别分布。
- **案例八**：回归任务只看训练集误差 → 命中 E11/E12，提示围绕误差量纲与留出验证集，迁移题换成用电量预测。
- **案例九**：K-means 只看轮廓系数 → 命中 E14，提示围绕内部指标局限、簇数选择与标准化。
- **案例十**：先标准化后划分 → 命中 E15，提示围绕参数估计范围与"先划分、只在训练集上拟合"。
