# 知行桥 演示脚本（5—7 分钟录屏用）

**演示前准备**

```bash
cd web && pnpm install && pnpm build
cd ../server && go run .          # 单端口演示：http://127.0.0.1:8080
```

确认首页徽标显示「规则模板模式」（未配置 API Key 时无需任何外部服务），数据库为空（如需清空：首页 → 学习记录 → 清空全部）。

> 讲解口径：以下案例数据均为**人工构造的教学演示数据**，不是真实训练实验结果。系统展示的所有指标都由程序计算，未调用大模型（界面会标注运行模式与是否真实调用）。

---

## 第 0 段（0:00—0:30）产品定位

打开首页，指向标题与一句话介绍：**以实验结果为证据，通过诊断、分层提示和迁移检验，帮助学生真正理解人工智能实验。**

强调三点：不是课程问答机器人，不替学生写代码；判断依据来自学生提交的证据；本期聚焦「机器学习分类实验」。

---

## 第 1 段（0:30—1:10）加载演示案例并提交

1. 点击「体验演示案例」→ 自动载入**案例一：类别极不平衡的三分类任务**。其他案例可在提交页点击「加载演示案例」选择。
2. 快速带过表单：实验名称、类别分布（A 900/B 90/C 10，共 1000）、混淆矩阵、评价指标、学生解释「我的模型准确率达到 90%，所以我认为模型效果很好，可以直接使用了」。
3. 说明：混淆矩阵既可粘贴也可用表格填写，界面实时调用后端计算校验（可以故意输入一个负数或让某行少一列，展示中文错误提示，并强调**已填内容不会被清空**）。
4. 点击「开始诊断」。

---

## 第 2 段（1:10—2:20）诊断结果

1. 顶部先看「任务类型」标签：诊断、提示与迁移题都限定在这一任务范围内。
2. 「主要问题」引用具体数据（准确率 90%、B/C 召回率为 0），并提示**规则只能定位问题，不能替代学生自己的判断**。
3. 往下看「逐条主张诊断」：学生的每个主张被单独判断（本例一条命中“只用整体准确率”，另一条可能未命中），每条都给出学生原话、判断、原因、证据边界与下一步追问。
4. 右侧「材料必要性」区分必需与可选材料；「知识点状态」勾出已掌握/部分掌握/尚未涉及。

依次讲解：

- **问题类型**：实验结果解释问题 + 评价指标选择问题。
- **证据**：分为「学生原话」与「由你提交的矩阵计算」两类来源。读出关键证据：总样本 1000，正确 900，准确率 90.0%；真实类别 B 的 90 个样本全部被预测为类别 A，召回率 0%。
- **诊断理由**：准确率对每个样本等权，被多数类主导。
- **掌握情况**：尚未体现。
- **指标表**：逐类召回率 100% / 0% / 0%，宏平均 F1（≈0.316）与加权平均 F1（≈0.853）的差距——**这正是类别不平衡的信号**。指出表格下角标注「由程序计算」与零分母约定说明。
- **建议下一步**：逐类计算召回率并判断少数类是否可用。

---

## 第 3 段（2:20—3:40）分层辅导

1. 点「给我一级提示」——只给观察方向（看 B、C 两行的去向），读出提示尾部引用的真实数据。
2. 在输入框写学生回答：「B 和 C 都被预测为 A，所以模型可能没有识别出这两个类别」，点「我再想一想 / 提交我的解释」→ 系统给出「有所修正」反馈与仍缺要点。
3. 点「给我二级提示」——解释准确率与召回率的关系，并要求回到证据。
4. 点「查看局部示例」——给出 `0 / 90 = 0%` 的局部计算（三级提示才有计算），强调**答案不是一次给完的**。
5. 可选演示教师介入：连续两次提交「我觉得模型没问题」，出现「建议教师介入」提示与原因。

---

## 第 4 段（3:40—4:50）迁移测试

1. 点「进入迁移测试」——题目由规则模板按当前任务类型（本例是分类指标）与命中的问题类型组合生成，情境与数据条件都与原题不同。
2. 展开「这道题是怎么生成的？」：读出题目来源（规则模板组合生成）、选题依据（任务类型 + 命中的问题类型）与重复检查结果（与示例情境的相似度）。
3. **先强调规则**：此时页面上只有题目、评分维度与评分口径声明，**没有参考答案入口**；提交自己的答案后才出现「查看参考答案」。
4. 输入答案：正样本只占很小比例，属明显不平衡；准确率会误导；主指标看召回率，用精确率控制误报，按可接受的错误代价调整阈值，并结合混淆矩阵核对两类错误数量。
5. 提交 → 三个维度逐条给分并说明理由，此时才出现「查看参考答案」。
6. 读出评分口径声明：分数只代表本次演示任务的规则化反馈。
7. （可选）再新建一个「案例七：RNN 训练损失异常与梯度裁剪」，展示切换到训练稳定性任务后：诊断引用日志中的具体数值、三级提示不出现混淆矩阵/类别分布、迁移题换成训练异常证据组合。

---

## 第 5 段（4:50—6:00）学习反馈与教师视图

1. 点「完成本次学习」→ 学习反馈页：学习目标、关键证据、主要误区与支撑证据、实际提示轨迹、修正情况、迁移表现与评分依据、当前掌握情况、后续学习建议、建议教师关注的问题。
2. 演示「复制反馈」与「导出 Markdown / TXT」。
3. 打开「教师视图」：记录摘要、提示等级、迁移表现、共性问题计数，并读出免责说明——**统计只来自本机已保存的记录，不是真实班级或成绩统计**。
4. 打开「学习记录」：展示本次记录（状态「已完成学习」、迁移 6/6），先刷新验证记录仍在（服务端 SQLite 持久化），再演示删除/清空并验证记录已移除。

---

## 收尾（6:00—6:30）

回到首页，说明三种模式：`demo` 预置演示、`rule` 规则模板（无 Key 即可运行）、`llm` 大模型增强（配置 Key 后启用，任一校验失败自动回退且不丢失内容）；以及诚实边界：未运行学生代码、未编造未提供的数据、评分不是考试成绩。

---

## 备选片段（时间有余时）

- **案例二**：只提交准确率 → 诊断为「证据不足」并追问类别分布与任务目标，示范系统不武断下结论。
- **案例三**：误读混淆矩阵 → 指出陈述与证据矛盾（100 个样本不在对角线上），语气中性、不贬低学生，并建议教师介入。
- **案例五**：环境报错 → 直接给出可执行的排障步骤（`pip install`、打印路径、检查形状），不用苏格拉底式提问。
- **案例八**：回归任务只看训练集误差 → 诊断命中“误用 R²/训练集误差”规则，三级提示围绕误差量纲与留出验证集，迁移题换成用电量预测情境（不会出现混淆矩阵或逐类指标）。
- **案例九**：K-means 分群只看轮廓系数 → 诊断命中“只看内部指标数值就下结论”规则（E14），三级提示围绕内部指标的局限、簇数选择与标准化，迁移题换成会员分群/主题聚类情境（不会出现混淆矩阵、逐类指标或回归误差）。
- **案例十**：先标准化后划分 → 诊断命中“先在全量数据上做预处理再划分”规则（E15），三级提示围绕参数估计范围与“先划分、只在训练集上拟合”，迁移题换成用户流失预测与逾期预测情境（不会出现聚类或回归专用指标）。
